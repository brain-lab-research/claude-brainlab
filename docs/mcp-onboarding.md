# Подключиться к базе знаний BRAIn Lab

Lab Knowledge MCP даёт агенту доступ к общей библиотеке, результатам исследований и решениям лаборатории. Он может находить уже сделанную работу и сохранять новые результаты с источниками.

[Посмотрите Atlas и попробуйте поиск](https://brain-lab-research.github.io/claude-brainlab/lab-showcase/#mcp-live) до подключения. Сайт открыт всем и содержит только вымышленные учебные данные.

## Получить доступ

1. Откройте [бот доступа](https://t.me/brainlab_server_access_bot) в личном чате.
2. Если профиль ещё не заполнен, сначала откройте **«Мой профиль»** и укажите имя, фамилию и рекомендателя. Затем нажмите **«Получить доступ»**. В общей форме укажите ник и выберите **«База знаний MCP»** в списке «Серверы и база знаний». Под ней выберите роль и нажмите **«Подать заявку»**. Для одного MCP срок серверного доступа не нужен. Кнопка **«База знаний MCP»** в меню открывает ту же форму с уже выбранным MCP.
3. Андрей проверит заявку и выберет роль: запрошенную или другую. Бот пришлёт сообщение с вашим именем, ником, фактической ролью, личным ключом, инструкцией и группой тестирования.

Аккаунт создаётся по постоянному Telegram ID. Изменение ника не меняет аккаунт. SSH-доступ к вычислительным серверам, Obsidian и Zotero для подключения не требуются.

## Подключить агента

В настройках MCP-клиента выберите **HTTP / Streamable HTTP**. Название подключения: `lab-knowledge`. Адрес возьмите из сообщения бота. Добавьте заголовок:

```text
Authorization: Bearer ВАШ_ЛИЧНЫЙ_КЛЮЧ
```

Ключ даёт доступ от вашего имени. Храните его в настройках своего клиента, не в репозитории и не в сообщении группе.

### Codex CLI

В Bash задайте адрес из бота и введите ключ скрытым вводом:

```bash
export LAB_MCP_URL='АДРЕС_ИЗ_БОТА'
read -r -s -p 'Личный ключ MCP: ' LAB_MCP_TOKEN
export LAB_MCP_TOKEN
codex mcp add lab-knowledge --url "$LAB_MCP_URL" --bearer-token-env-var LAB_MCP_TOKEN
codex
```

Переменная с ключом должна быть доступна процессу Codex при каждом запуске. Этот пример запускает CLI из того же терминала. Для приложения, открытого из Dock или меню Windows, настройте подключение и секрет в самом клиенте.

### Claude Code

После задания `LAB_MCP_URL` и `LAB_MCP_TOKEN`:

```bash
claude mcp add --transport http --scope user lab-knowledge "$LAB_MCP_URL" \
  --header "Authorization: Bearer $LAB_MCP_TOKEN"
```

Перезапустите Claude Code и проверьте соединение через `/mcp`.

### Навыки лаборатории

Для готовых сценариев установите [набор навыков](../README.md#install). Задайте `LAB_MCP_URL` и `LAB_MCP_TOKEN` в локальном `.env` по примеру установщика. Если Claude Code уже установлен, установщик зарегистрирует Lab MCP штатной командой клиента и проверит сохранённую конфигурацию. Существующее подключение с именем `lab-knowledge` он сохранит: изменить его можно через `/mcp`.

Навык `lab-knowledge` объясняет агенту виды записей и порядок сохранения, `create-project` помогает оформить проект и его связи.

## Первые действия

Попросите агента:

> Покажи проекты лаборатории через Lab Knowledge MCP. Найди мой проект по названию и открой его контекст. Пока ничего не записывай.

Затем можно искать конкретную информацию:

> Найди, какие эксперименты и статьи уже есть по моей теме. Приведи ID записей, источники и ограничения результатов.

Чтобы сохранить результат в доступный вам проект:

> Запиши этот результат в проект. Сохрани реальные метрики, источник и ограничения. Прочитай запись обратно и назови её ID.

Если проекта ещё нет, создайте его через `create-project` или инструмент MCP `create_project`. Для существующего проекта используйте его ID: повторная карточка не выдаёт доступ к исходной работе.

## Роли лаборатории

| Роль | Для чего |
|---|---|
| Участник (`member`) | Читать общую базу, добавлять литературу, создавать проекты и работать в них |
| Координатор (`manager`) | Права участника, приглашение людей и управление ключами участников; не управление ключами ведущих или других координаторов |
| Ведущий лаборатории (`lead`) | Управление всеми проектами, доступами и глобальными ролями |

Роль выбирается в заявке, но выдаётся только после решения Андрея. Повторная выдача ключа не понижает существующую роль. Если доступ уже есть, через форму можно запросить повышение; до одобрения текущий ключ сохраняет прежние права. Доступ действует до отзыва ключа.

Учётная запись связана с постоянным Telegram ID. Ник служит для понятного отображения и не позволяет получить чужую учётную запись. Существующие лабораторные аккаунты привязываются только после проверки владельцем. При повышении аккаунта с несколькими ключами сначала проверяют, кому они были выданы: каждый действующий ключ получает новые права аккаунта.

## Права внутри проекта

`viewer` читает, `contributor` добавляет, меняет и удаляет записи, `lead` проекта также приглашает участников. Роль руководителя проекта не равна глобальному ведущему лаборатории.

## Права участника

| Действие | Кто может |
|---|---|
| Читать общую базу и искать по ней | Каждый участник |
| Добавлять статьи и утверждения в общую библиотеку | Каждый участник |
| Создать свой проект | Каждый участник, с ролью владельца в новом проекте |
| Добавлять, изменять и удалять записи проекта | Его владелец и приглашённые соавторы (`contributor`) |
| Только читать проект | Роль `viewer` и остальные участники лаборатории |
| Пригласить соавтора | Владелец проекта или ведущий лаборатории |
| Удалить свой проект | Создатель проекта; содержимое требует отдельного явного удаления |
| Управлять чужими проектами и глобальными ролями | Ведущий лаборатории |

Если агент читает проект, но не может сохранить результат, попросите владельца проекта добавить ваш аккаунт из сообщения бота как `contributor`. Глобальная роль `member` сама по себе не даёт права изменять все проекты.

## Если подключение не работает

- **401**: ключ неверен, отозван или аккаунт отключён. Проверьте ключ через `/mcp` в боте.
- **Отказ записи в проект**: проверьте ID проекта и свою роль в нём. Владелец проекта может пригласить вас.
- **Ошибка полей записи**: попросите агента прочитать текущую схему инструмента. Не добавляйте выдуманные метрики или цитаты для обхода проверки.
- **Бот не доставил подключение**: одобренная заявка сохраняется. Андрей может повторить выдачу через `/mcp_requests`, сохранив тот же ключ.

Показать ключ повторно и отозвать его можно через `/mcp`. После отзыва агенты с этим ключом потеряют доступ. Для нового ключа отправьте новую заявку.

[Atlas](https://brain-lab-research.github.io/claude-brainlab/lab-showcase/#memory) объясняет устройство базы на учебных данных. Подключённый MCP работает с общей базой лаборатории. Ссылка на группу обратной связи приходит в личном сообщении после одобрения.
