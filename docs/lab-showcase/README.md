# Витрина исследовательской лаборатории

Так выглядит система, в которой работа лаборатории записывается не в переписку, а в общую
базу: у утверждения есть критерий опровержения, у прогона — замороженный протокол, у
измерения — прогон, из которого оно взялось, а правило появляется только после измерения.

**Данные здесь выдуманы.** Это Демо-лаборатория: одно научное направление, одна тема,
один проект с 6 утверждениями и
8 статьями. Настоящая база лаборатории остаётся приватной.

## Открыть

Сервер не нужен, сайт статический:

```bash
open index.html          # macOS
xdg-open index.html      # Linux
```

## Поставить на свою базу

Витрина читает четыре файла данных и больше ничего не знает об источнике:

| Файл | Что в нём |
|---|---|
| `data/base-snapshot.js` | `window.LAB_BASE` — записи: проекты, утверждения, прогоны, измерения, правила, термины |
| `data/library-snapshot.js` | `window.LAB_LIBRARY` — статьи и разобранные из них утверждения |
| `data/atlas-tree.js` | `window.LAB_TREE` — дерево разделов с аннотациями: по нему отвечают широкие запросы |
| `data/atlas-public.js` | `window.LAB_ATLAS_DATA` — реестр инструментов лаборатории |

Соберите эти четыре файла из своей базы в той же схеме, замените — и страница живого MCP
покажет ваши записи. Схема видна прямо в файлах этой сборки: они маленькие и читаются
целиком.

## Живой поиск

В этой сборке живой службы нет, поиск идёт по локальному снимку словами. У себя её роль
играет любой сервис, который отвечает на запрос списком записей с оценкой релевантности:
витрина ждёт от него `items` с полями `entity_type`, `entity_id`, `title`, `snippet`,
`score` и `extra`.

Сама лаборатория использует MCP-службу `lab-knowledge`: e5-эмбеддинги, BM25 через RRF,
расширение по графу связей и переранжирование кросс-энкодером. Порядок ответа задаёт
кросс-энкодер, а не совпадение слов — поэтому в ответе подсвечивается не совпавшее слово, а
то, чем утверждение закрыто.
